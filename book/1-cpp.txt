== *1.4. Builtins*
``__builtin_clzll(x)`` - кол-во $0$ после старшей $1$ в битовом представлении. При $x = 0$ - UB.
``__builtin_ctzll(x)`` - кол-во $0$ перед младшей $1$ в битовом представлении. При $x = 0$ - UB. Поиск делимости на $2^k$.
``__builtin_parityll(x)`` - чётность кол-ва $1$ в битовом представлении. Аналогично ``__builtin_popcount(x) & 1``.
``__builtin_mul_overflow(a, b, &res)`` - умножает a на b, сохраняет результат в res. Возвращает true, если произошло переполнение, и false, если всё ок.
Целый $floor(log_2(x))$: ``__lg(x)`` - одна инструкция (1 нс, ``log2l`` - 28 нс). Есть для int, long, long long и их unsigned, ответ того же типа, что и $x$. При $x = 0$ - UB, для ``__int128`` нет.
$floor(sqrt(x))$ для long: ``sqrtl(x)`` (точно для всех long: 64-битная мантисса ``long double``); ``sqrt`` в double (53 бита) на больших $x = k^2 - 1$ даёт $k$.

=== *1.4.1. Округление и деление*
``lround(x)`` / ``llround(x)`` - ближайшее целое в long / long long, половины от нуля: $2.5 -> 3$, $-2.5 -> -3$.
``floor(x)`` - вниз: $-2.5 -> -3$, ``trunc(x)`` и ``long(x)`` - к нулю: $-2.5 -> -2$ (клетка сетки для отрицательных - только floor). Целое ``a / b`` - это trunc: при одинаковых знаках равно floor, при разных - ceil. При $a = -7, b = 2$: ``a / b`` $= -3$, floor $= -4$, ceil $= -3$.
``(a + b - 1) / b`` - ceil только при $a >= 0, b > 0$. Ошибки: $a = -2, b = 2$: $0$ вместо $-1$; $a = 7, b = -2$: $-2$ вместо $-3$; $a = -7, b = -2$: $5$ вместо $4$.

=== *1.4.2. Большие константы, powl*
``1e18`` - это double (53 бита): ``long x = 1e18 + 7`` даёт $10^18$, ``1e17 + 3`` - $10^17$. Степени 10 до $10^22$ точны, double точен до $2^53 approx 9 dot 10^15$, поэтому ``int(1e9 + 7)`` - ок. Дальше ``long(1e18) + 7`` или ``1'000'000'000'000'000'007`` (разделители разрядов, C++14).
Кол-во цифр: ``to_string(x).size()``, не ``log10l(x) + 1``: ``log10l(999999999999999999)`` = 18.
``powl`` от целых в 45 раз медленнее бинарного возведения. Без своего: ``__builtin_powil(x, n)``: ``x`` - ``long double``, ``n`` - 32-битный (``long`` молча обрежется), $O(log(n))$ умножений, в 1.5 раза медленнее бинарного. Ответ точен, пока $< 2^64$: ``long(__builtin_powil(x, n))`` для степеней и корней в ``long``, не по модулю.
== *1.5. Runtime Errors*
*0xC0000005* - Access Violation. Причины: выход за границы массива, слишком большой массив в стеке, обращение к NULL-указателю.
*0xC00000FD* - Stack Overflow. Причины: бесконечная/очень глубокая рекурсия, слишком большой массив в стеке.
*0xC0000374* - Heap Corruption. Повреждение кучи (динамической памяти), программа часто падает не в момент ошибки, а позже (когда пытается удалить или выделить память). Причины: запись за границы массива, вызвал ``delete`` второй раз (или просто к мусору).
*0xC0000094* - Integer Divide by Zero.
*0xC000001D* - Illegal Instruction. Причины: выход из не-void функции без return. (`-Werror=return-type` в Other compiler options)
*0xC0000417* - Invalid C Runtime Parameter. Причины: assert failed или непойманное исключение.

== *1.7. Move(v)*
В нагруженных рекурсивных функциях, возвращающих vector / set, писать ``return move(v);``. Без него контейнер копируется за $O(n)$, если возвращается не просто локальная переменная: ``return x ? a : b;``, ``return res[v];``, ``return p.f;``.
Ссылка без const не принимает rvalue (временный объект): для ``int f(string &s)`` вызов ``f(t)`` - ок, ``f(t + "#")`` и ``f("abc")`` не компилируются. ``int f(const string &s)`` принимает и то, и другое.
== *1.8. clamp*
``clamp(x, l, r)`` (C++17, ``<algorithm>``) - $x$, прижатый к $[l, r]$: ``x < l ? l : r < x ? r : x``. Все 3 аргумента одного типа: при ``#define int long`` писать ``clamp(x, int(0), n)``. При $l > r$ - UB (GCC вернёт $l$ при $x < l$, иначе $r$, с ``-D_GLIBCXX_ASSERTIONS`` - падение). NaN возвращается как есть. ``clamp(x, l, r, comp)`` - со своим сравнением.

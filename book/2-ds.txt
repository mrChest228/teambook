== *2.6. Wavelet matrix*
Массив не меняется, запросы на $[l, r)$ онлайн за $O(log(italic("MX")))$: ``kth(l, r, k)`` - $k$-е по возрастанию (с $0$), ``cnt(l, r, x)`` - кол-во чисел $< x$. Значения заранее сжать в $[0, italic("MX"))$ (для ``near`` - не сжимать: сравниваются расстояния).
Через них: кол-во в $[x, y)$ - ``cnt(l, r, y) - cnt(l, r, x)``, ближайшее к $x$ - ``near(l, r, x)`` (наибольшее $< x$ - ``kth(l, r, c - 1)``, наименьшее $>= x$ - ``kth(l, r, c)``, $c = $ ``cnt(l, r, x)``); медиана - ``kth(l, r, (r - l) / 2)``.
Устройство: на уровне $i$ числа стабильно разложены по биту ``H - 1 - i``: слева нули (``mid[i]`` штук), справа единицы. Если $L, R$ - единиц до $l$ и до $r$, отрезок переходит в $[l - L, r - R)$ среди нулей или в $[italic("mid") + L, italic("mid") + R)$ среди единиц. Спуск как в боре по битам ответа.
Против персистентного ДО (те же запросы и асимптотика), $n = q = 2 dot 10^5$: память $29$ МБ против $93$, запросы $184$ мс против $219$, без указателей и пула вершин. $italic("MX")$ - граница значений: память $4 N log_2 italic("MX")$ байт. Массив из $0$ и $1$ ($italic("MX") = 2$) - $1.6$ МБ, числа до $10^9$ (``MX = 1e9 + 9``) - $24$ МБ. ДО с сортированными векторами ($O(log^2)$ / $O(log^3)$) - $2043$ мс.
Задачи: $k$-я порядковая на отрезке (SPOJ MKTHNUM), кол-во чисел из $[x, y]$ на отрезке (SPOJ KQUERY), ближайшее к $x$ на отрезке. С префиксными суммами значений на каждом уровне - сумма $k$ наименьших на отрезке (сумма расстояний до медианы).

== *2.7. Алгоритм Мо*
Запросы на отрезках офлайн, если ответ легко пересчитать при добавлении и удалении крайнего элемента.
Сортируем запросы по блоку $floor(l \/ K)$, внутри блока по $r$. Левая граница за запрос сдвигается на $<= 2K$, правая за блок - на $<= n$: всего $O(q K + n^2 \/ K)$ сдвигов, при $K = n \/ sqrt(q)$ это $O(n sqrt(q))$.
В нечётных блоках $r$ сортируем по убыванию: правая граница не возвращается в начало, это быстрее почти вдвое.
Сначала расширяем отрезок, потом сужаем, иначе он на время становится пустым с $l > r + 1$.

== *2.8. RMQ*
Минимум на отрезке без изменений. Обе функции возвращают индекс минимума, максимум - поменять знак в ``better``.
=== *2.8.1. Разреженная таблица*
$italic("sp")_(l, i)$ - минимум на $[i, i + 2^l)$. Отрезок $[l, r]$ покрываем двумя отрезками длины $2^t$, $t = floor(log_2(r - l + 1))$: они пересекаются, минимуму это не мешает. $O(n log(n))$ памяти и времени, запрос $O(1)$.

=== *2.8.2. За $O(n)$ и $O(1)$*
Короткий запрос, $r - l < 64$: идём слева направо со стеком минимумов (в стеке $a_j$, которые не больше всего правее себя). $italic("msk")_i$ - стек в момент $i$ как маска последних 64 позиций. Минимум на $[l, r]$ - самый левый элемент стека $italic("msk")_r$ не левее $l$, то есть старший бит маски без битов $> r - l$.
Длинный запрос: первые 64 элемента, последние 64 и целые блоки по 64 между ними - разреженная таблица на $n \/ 64$ блоках, это $O(n \/ 64 dot log(n))$.
$n = 10^6$: построение 0.01 с, $10^7$ запросов - 0.23 с. У разреженной таблицы 0.04 с и 0.09 с, но память $n log(n)$. $n = 10^7$: 0.12 с и 0.36 с против 0.52 с и 0.22 с. Блоки по 16 или 32 вместо 64 время не меняют: оно уходит на промахи кеша, их число то же.

== *2.9. Персистентное ДО*
Изменение создаёт $log$ новых вершин на пути от корня, остальные общие со старой версией. Вершина 0 - пустое дерево, её дети - она сама.
=== *2.9.1. $k$-я статистика на отрезке и на пути*
ДО по значениям, в вершине кол-во. Версия $i$ - префикс длины $i$: ``root[i + 1] = add(root[i], a[i])``. На $[l, r]$ кол-ва - разность версий $r + 1$ и $l$, спускаемся по обеим сразу: ``kth(root[r + 1], 0, root[l], 0, k)``.
Путь в дереве: версия вершины - значения на пути от корня, ``root[v] = add(root[par[v]], a[v])``. На пути $x - y$ с $c = "lca"(x, y)$: ``kth(root[x], root[y], root[c], root[par[c]], k)``, для корня вместо ``root[par[c]]`` - 0.
Значения заранее сжать в $[0, italic("MX"))$.

=== *2.9.2. MEX на отрезке*
ДО по значениям, в листе - последняя позиция значения, в вершине минимум. Версия $r$ построена по префиксу до $r$. MEX на $[l, r]$ - самое левое значение с последней позицией $< l$: спуск по версии $r$.
Значения $>= n$ на MEX не влияют. $italic("MEX")(a) <= sqrt(2 sum a_i) + 1$: нужны все числа $0..italic("MEX") - 1$.

== *2.10. Disjoint Sparse Table*
Массив не меняется, операция ассоциативна, но объединение дорогое или нет идемпотентности (сумма, произведение матриц, ДП на отрезке). Запрос - одно объединение.
Уровень $k$: блоки длины $2^(k + 1)$, от середины блока считаем операцию на суффиксах левой половины и префиксах правой. Запрос $[l, r]$ берём на уровне, где $l$ и $r$ в одном блоке по разные стороны середины - это старший бит $l xor r$ (то же, что LCA листьев $l$ и $r$ в ДО).
Пример: $n <= 10^5$, $m <= 100$, запросы - кол-во подпоследовательностей на $[l, r]$ с суммой, кратной $m$. Значение - массив из $m$ остатков. Добавить один элемент - $O(m)$, склеить два отрезка целиком - $O(m^2)$, склеить только ради остатка 0 - $O(m)$. В ДО запрос $O(m^2 log(n))$, здесь построение $O(n log(n) dot m)$ и запрос $O(m)$.

== *2.11. Сортировки за $O(n)$*
=== *2.11.1. Поразрядная*
Число - цифры по основанию $K$, сортируем подсчётом по цифрам от младшей к старшей. Сортировка устойчива, поэтому порядок по младшим цифрам сохраняется. $O((n + K) log_K (italic("MX")))$.
64-битные случайные числа, $n = 10^7$: ``sort`` 0.68 с, поразрядная 0.32 с. $n = 10^6$: 0.06 с и 0.04 с.

=== *2.11.2. Макс. разность соседних в отсортированном*
$n <= 10^7$, без сортировки. Делим значения от $italic("mn")$ до $italic("mx")$ на блоки длины $italic("sz") = ceil((italic("mx") - italic("mn")) / (n - 1))$. Ответ $>= italic("sz")$, а внутри блока разности $< italic("sz")$, поэтому сравниваем только максимум блока с минимумом следующего непустого.

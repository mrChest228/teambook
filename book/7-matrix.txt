= *7. _Matrices_*
== *7.0. Умножение и степень*
$ c_(i,j) = sum_k a_(i,k) b_(k,j), mat(1, 1; 1, 0)^n = mat(F_(n + 1), F_n; F_n, F_(n - 1)) $
Допустим нужно $q$ раз возводить одну и ту же матрицу в степень и домножать на вектор. Наивное решение: $O(q n^3 log(n))$, однако если мы предпросчитаем двоичные степени матрицы, а затем $log(n)$ раз домножим на них вектор, то получим асимптотику $O(n^3 log(n) + q n^2 log(n))$.

== *7.1. Гаусс по xor*
=== *7.1.1. Базис чисел*
Числа - векторы из битов, сложение - xor. Базис - мин. набор чисел, xor подмножеств которого даёт всё то же, что и xor подмножеств исходных $n$ чисел.
Храним ``b[i]`` - число базиса со старшим битом $i$ (или 0). ``add(x)``: идём по битам сверху, если бит $i$ в $x$ есть и ``b[i]`` есть - xor с ним, если ``b[i]`` нет - кладём туда $x$. Дошли до 0 - $x$ уже выражается, базис не изменился.

Свойства ($r$ - размер базиса):
различных xor подмножеств ровно $2^r$;
каждое значение получается ровно $2^(n - r)$ подмножествами исходных чисел (в т. ч. 0, вместе с пустым);
базис объединения - ``add`` всех чисел второго базиса;
макс. xor: идём сверху и берём ``b[i]``, если значение растёт.

Пример: сколько непустых подмножеств $a$ дают в произведении точный квадрат, $n, a_i <= 10^7$.
Число - вектор чётностей степеней простых. Произведение квадрат $<=>$ xor векторов равен 0, ответ $2^(n - r) - 1$.
Простых до $10^7$ много, но у числа не более двух простых делителей $> 215$ (третий дал бы $> 10^7$), а простых $< 215$ всего 47 - это маска в ``long``.
Большие простые $p, q$ числа - ребро $p - q$ (или $1 - p$, $1 - 1$) с весом-маской. Держим СНМ с xor до корня. Ребро между разными компонентами - новый вектор базиса, просто объединяем. Ребро внутри компоненты замыкает цикл, большие простые в нём сокращаются, остаётся маска - xor весов по циклу, её кладём в обычный базис на 47 бит.
$r$ = кол-во объединений + размер базиса масок.

=== *7.1.2. Быстрый Гаусс на битсетах (метод четырёх русских)*
Обычный Гаусс на ``bitset``: для каждого столбца xor опорной строки со всеми, где в нём 1 - $O(n m dot m \/ 64)$.
Идея: обрабатывать сразу $K$ столбцов и делать с каждой строкой один длинный xor вместо $K$.

Блок столбцов $c..c + K - 1$:
1) Для каждой оставшейся строки выписываем её $K$ бит блока в число ``pre[i]``.
2) Гаусс только на числах ``pre``: нашли строку с битом $j$ - она опорная, вычитаем её ``pre`` из остальных, а в ``his[i]`` запоминаем, какие опорные строки блока вычли. Длинные строки не трогаем.
3) Опорная строка нужна настоящая, поэтому в момент выбора делаем ей отложенный xor: ``a[v] ^= t[his[v]]``.
4) ``t[mask]`` - xor опорных строк блока из ``mask``, каждая новая опорная строка удваивает таблицу: ``t[mask | 1 << p] = t[mask] ^ a[v]``.
5) В конце блока каждой оставшейся строке один xor: ``a[i] ^= t[his[i]]``.

На блок: $n$ длинных xor и $2^K$ на таблицу, блоков $m \/ K$. Итого $O((n + 2^K) dot m \/ K dot m \/ 64)$, при $K approx log_2 n - 3$ это $O(n m^2 \/ (64 log n))$.
$n = m = 4000$: 0.06 с вместо 0.16, $n = m = 8000$: 0.37 с вместо 1.32.
Результат - ступенчатый вид: опорный столбец строки $i < r$ - ``a[i]._Find_first()``, строки $i >= r$ нулевые.
